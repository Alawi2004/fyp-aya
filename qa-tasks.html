T-003Critical
Remove hardcoded HMAC secret from client — move QR signing to server
frontend/src/screens/passenger/TicketScreen.js · Line 21
▼
Problem
const HMAC_SECRET = 'yalla-transit-qr-secret-2026' is bundled in the JavaScript. Anyone who unpacks the APK/IPA can extract this string and forge arbitrarily valid QR tickets for any booking ID and any seat.
Steps to reproduce
  1. Download the APK. Run apktool d app.apk.
  2. Search extracted JS bundle: grep -r "yalla-transit-qr-secret" .
  3. Use extracted secret to craft a valid HMAC token for any bookingId.
  4. Present forged QR — driver scanner accepts it.
Exact fix
1. Delete HMAC_SECRET, computeHmac(), and the entire generateToken() function from TicketScreen.

2. On booking confirmation, call POST /api/bookings/:id/qr-token. The server signs the payload with its private secret and returns a short-lived token.

3. The client displays the returned token string as a QR. It never computes a signature itself.

4. The driver scanner POSTs the scanned token to POST /api/driver/scan-qr. The server validates the HMAC and marks the ticket as used.

T-004Critical
Remove insecure HMAC fallback — it produces a deterministically forgeable token
frontend/src/screens/passenger/TicketScreen.js · Line 36
▼
Problem
When expo-crypto is unavailable, the fallback is:
return `${msg.length.toString(16).padStart(8, '0')}${payload.exp.toString(16)}`.slice(0, 32)
This is purely deterministic from public info (message length + expiry timestamp). Any attacker who knows the booking structure can pre-compute this "signature" without any secret.
Exact fix
Make expo-crypto a hard dependency in app.json. If it fails to load, disable QR display entirely and show:

"QR generation unavailable on this device. Please update the app to continue."

Never silently degrade to an insecure fallback for a security-critical feature.

T-026Medium
Add ±30 second clock skew tolerance to QR validation on the server
frontend/src/screens/passenger/TicketScreen.js · Lines 39–41 + backend QR validation
▼
Problem
The QR expiry window is calculated from Math.floor(Date.now() / 1000) on the passenger's phone. Mobile phones can have clock drift of 30–60 seconds. If the passenger's clock is ahead of the driver's scanner, the QR appears expired mid-scan even though it was generated within the valid window.
Exact fix
On the backend, during QR validation, accept tokens from the current window OR the previous window:

const now = Math.floor(Date.now() / 1000);
const currentWindow = Math.floor(now / 60) * 60 * 1000 + 60000;
const prevWindow = currentWindow - 60000;
if (token.exp !== currentWindow && token.exp !== prevWindow) → REJECT

S-003Security
Prevent QR replay attacks — add a used-ticket registry on the server so the same QR token cannot be scanned twice
backend/src/routes/ (scan-qr endpoint)
▼
Fix
In the POST /api/driver/scan-qr handler:

1. After validating the HMAC and expiry, check a Redis cache (or DB table) for the token hash.
2. If found → return 409 "Ticket already used".
3. If not found → mark it used (TTL = 60 seconds) and return success.

This makes QR tokens single-use within their validity window, preventing a passenger from sharing their screen with multiple people.

Reduce battery drain in BusTrackingScreen — pause all 4 intervals when app goes to background
frontend/src/screens/passenger/BusTrackingScreen.js · Lines 199–229
▼
Problem
4 intervals run simultaneously: GPS (3s), ETA (30s), camera seat count (5s), mock countdown (30s). All continue polling even when the app is backgrounded, draining battery unnecessarily.

import { AppState } from 'react-native'; useEffect(() => { const sub = AppState.addEventListener('change', state => { if (state === 'background') { clearInterval(gpsInterval.current); clearInterval(seatInterval.current); } else if (state === 'active') { // restart intervals } }); return () => sub.remove(); }, []);

P-002Perf
Cache auth token in memory — avoid AsyncStorage read on every API request
frontend/src/api/apiClient.js · Lines 135–139
▼
Problem
The request interceptor calls await AsyncStorage.getItem('authToken') on every single API request. AsyncStorage is async disk I/O — it adds ~2–5ms of latency to every call and can block on slow storage.
Fix
// Module-level cache let _cachedToken = null; export const setTokenCache = (t) => { _cachedToken = t; }; export const clearTokenCache = () => { _cachedToken = null; }; // In interceptor: const token = _cachedToken ?? await AsyncStorage.getItem('authToken'); if (token) { _cachedToken = token; config.headers.Authorization = `Bearer ${token}`; } // In AuthContext.login(): call setTokenCache(token) // In AuthContext.logout(): call clearTokenCache()
